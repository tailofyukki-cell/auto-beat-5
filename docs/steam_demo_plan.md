# Steam体験版: 90秒制限の実装計画

## 状態

2026-10-02: 他機能への影響があるため、ユーザーの指示により実装を保留。
製品版の開発が落ち着いたリリース準備段階で、体験版ビルドの分離と一緒に実装する。
本資料の追加時点ではゲームのコード、60秒のお試し機能、ビルド処理を変更していない。

## 決定済み

- 体験版で持ち込み音源を遊ぶ場合、1回のプレイは最大90秒。
- 90秒以下の音源は最後まで遊べる。長さがちょうど90秒の音源も含む。
- 90秒を超える音源は、90秒以内にフェードアウトして終了する。
- ユーザーが短く切り出した音源を最後まで遊べても許容し、その防止処理は設けない。
- 製品版の通常プレイに、この時間制限を適用しない。

## 今すぐ定数変更しない理由

| 現在の実装 | 影響・注意点 |
|---|---|
| `src/app.py` の `TRIAL_PLAY_LIMIT_SECONDS = 60.0` | 配布体験版の設定ではなく、製品版にもある「お試しプレイ」の制限。90へ変えるだけでは目的と異なる |
| `start_game()` / `start_trial_game()` | 通常プレイとお試しは別経路。体験版の通常プレイにも上限を適用する必要がある |
| `start_practice()` | 練習モードはお試しとは別経路。区間指定・ループで90秒制限をどう扱うか決める必要がある |
| `finish_game()` | お試しはランキング・報酬に反映しない。通常プレイへ流すと、途中終了の記録や解放が混ざる |
| `src/persistence.py` の `data_namespace()` | 保存先の区別であり、体験版の機能制限を表す仕組みではない |
| `build_trial_package.bat` | 旧配布用のパッケージ処理。ファイル名にTrialがあっても90秒体験版の実装済みを意味しない |

## 実装時の方針案（未実装）

1. 製品版／体験版を明示するビルド設定を導入し、ゲーム内のお試し状態とは分ける。
2. 製品版の通常プレイ・既存60秒お試し・練習を維持し、体験版の持ち込み曲だけへ90秒上限を適用する。
3. 時間は実際の再生時計で数え、カウントダウン・一時停止時間を含めない。
4. 長い曲は終了直前に音量を下げ、90秒以内に終了。短い曲には制限用のフェードをかけない。
5. 途中終了時に未到達ノーツを大量MISS扱いしないよう、対象ノーツと途中のHOLDの扱いを設計する。
6. 体験結果を製品版のランキング・報酬・フルコンボ記録と混在させない。
7. 体験版の保存先と製品版への設定引き継ぎ方針を決め、既存セーブを壊さない。
8. 体験版ビルド、説明書、ストアの制限説明、配布物の受入テストをまとめて更新する。

## 未決定事項

- 区間の開始位置選択、区間練習・ループの利用範囲と90秒の数え方。
- 同梱デモ曲の時間制限を免除するか。
- 難易度・レーン数・マスコット・ご褒美など、時間以外の制限。
- 短い曲を完走した場合も体験専用結果にするか、体験版内で記録や報酬を持つか。
- 累計回数・時間制限を設けない案は提案段階。今回の90秒の決定とは分けて扱う。

## 受入確認

- 89.9秒・90秒の音源が最後まで再生され、制限用のフェードが入らない。
- 90秒超の音源がフェードアウトし、90秒以内に終了する。
- 一時停止・再開・リトライ後も入力が効き、時間制限と音量が正しくリセットされる。
- 90秒をまたぐHOLD、終端付近のノーツで誤判定やフリーズがない。
- 結果、ランキング、BP、解放、フルコンボ演出が未決定事項の確定後の仕様どおりになる。
- チュートリアルと全3種類の任意練習に影響しない。
- 製品版のフルプレイ・60秒お試し・区間練習・既存セーブが従来どおり動く。
- 製品版と体験版の両方を実際にビルドし、Python未導入PCで確認する。
