# AutoBeat 5 販売品質向上ロードマップ

**作成日:** 2026-08-19  
**対象:** Windows版 AutoBeat 5（手持ち音源から5レーン譜面を自動生成する音楽ゲーム）  
**目的:** 現行の「動作する技術試作」を、購入者が初回起動から価値を理解し、安心して継続プレイ・推薦できる**同人ゲーム商品**へ引き上げる。

## 結論

AutoBeat 5の核となる価値は、単なる自動解析ではなく、**「自分の好きな音楽を、すぐに演奏可能な体験へ変換できること」**です。販売前の最優先事項は機能数を増やすことではありません。購入者が音源を用意し、迷わず遊び始め、譜面・判定・同期に納得し、もう一曲試したくなる最初の15分を完成させることです。

現行版は、音源解析、5難易度、譜面生成、判定、設定、報酬ギャラリー、Windowsビルドまでを実装済みです。一方で、販売品質の観点では、**初回導線、実音源での譜面品質保証、購入者向け体験素材、障害時の安心感、販売ページの説得力**が不足しています。特に、自動譜面ゲームは曲によって品質差が生まれやすいため、技術的な機能紹介よりも、プレイヤーが調整・再挑戦・報告をしやすい設計が商品価値に直結します。

> 販売時に伝えるべき主語は「解析精度」ではなく、**『あなたのライブラリを、今日から演奏する』**です。

## 現在地の評価

| 領域 | 現在の強み | 販売前の不足 | 判定 |
|---|---|---|---|

| **P0** | 同期・判定の調整支援 | 「自分が下手なのか音ズレなのか」が分かる | クリック音付きのキャリブレーション、判定表示、設定へのショートカット | 音ズレを自己解決できる |
| **P0** | 譜面品質の安全網 | 曲による外れ譜面で離脱しない | 解析結果の信頼度表示、ノーツ密度プレビュー、速度・難易度の推奨、再生成オプション | 低品質時の逃げ道がある |
| **P0** | 収録体験用コンテンツ | 購入直後に自前音源がなくても価値を体験できる | 権利処理済みの短いテスト曲、チュートリアル譜面、ゲーム内デモ | 音源を持たない人も初回体験できる |

| **P1** | 曲別の遊びやすさ | 自動生成の品質差を吸収する | BPM・密度・推奨難易度、曲別のオフセット・速度保存 | 曲ごとの最適設定を再利用できる |

## 最初に着手すべき5項目

### 1. 「最初の1曲」を製品として作る

初回起動から音源を選ばせるだけでは、購入者は手持ちの曲、対応形式、解析待ち、譜面の当たり外れを一度に判断することになります。これはツールとしては自然でも、ゲーム商品としては導入障壁です。

権利処理済みの短いオリジナル曲または利用条件を明確に確認したテスト曲を1〜3曲収録し、次の順で誘導する構成を推奨します。

1. 「デモで遊ぶ」または「自分の曲を選ぶ」を最初に選ばせる。
2. デモではBEGINNER相当の固定チュートリアル譜面を使う。
3. D / F / Space / J / K、判定線、長押し、ポーズ、速度設定を1曲の中で体験させる。
4. リザルト後に「次はあなたの曲を解析する」を提示する。

これは自動譜面の魅力を隠すためではなく、購入者がゲーム側の基準を理解してから自分の曲へ進めるようにする施策です。市販曲・CD・配信音源を同梱する場合は、著作権に加えて音源製作者・アーティスト等の著作隣接権にも許諾が必要になるため、販売版には安易に含めない方針が安全です。[1]

### 2. 音ズレを「設定項目」から「解決できる体験」へ変える

Timing Offsetが存在するだけでは、多くの購入者は値をどう変えるべきか分かりません。音楽ゲームでは、判定の納得感が最重要の品質指標になります。

推奨する改善は、メトロノームに合わせてキーを押す**キャリブレーション画面**です。推定した平均ずれを候補値として表示し、「適用」「やり直す」「手動調整」の3択にします。曲別オフセットも保存できるようにすれば、Bluetooth機器や特定の音源だけで生じる差も救済できます。

加えて、リザルトで「早い／遅い」の偏りを小さなヒストグラムで示すと、購入者が自分の改善と機材遅延を切り分けられます。これは判定を甘くするより、信頼感を保ったまま遊びやすさを上げる方法です。

### 3. 自動譜面の品質を可視化し、逃げ道を用意する

自動生成は本作の差別化要因ですが、すべての曲で同じ演奏感を保証することはできません。販売版では解析後に以下を表示し、購入者が納得して選べる状態にするべきです。

| 表示・操作 | 目的 |
|---|---|
| 推定BPM、曲長、ノーツ数、最大同時押し数 | 解析結果を説明可能にする |
| 難易度ごとの密度と推奨ラベル | 初心者が適切な譜面を選べる |
| 5〜10秒の無音ノーツプレビュー | プレイ前に視認量を把握できる |
| 「控えめ」「標準」「にぎやか」生成プリセット | 曲の解釈を一つに固定しない |
| 「この譜面を評価する」導線 | 改良用の手動プレイ知見を集める |

最初の販売版ではオンライン収集を必須にせず、ローカルに評価を保存するだけでも構いません。後続アップデートで、ユーザーが明示的に共有を許可したときだけ匿名の譜面評価を送る方式へ発展できます。

### 4. 「遊べる」だけでなく「見せたくなる」リザルトへ育てる

現行の報酬ギャラリーは継続動機として良い土台です。次はリザルトに、曲名、難易度、ランク、精度、最大コンボ、生成条件をまとめた**結果カードのPNG保存**を加えるべきです。投稿機能そのものは不要です。ローカルで画像を生成し、プレイヤーが任意のSNSへ載せる形なら、アカウント連携やプライバシーの負担を増やしません。

これに合わせて、タイトル・選曲・判定エフェクトの色・書体・効果音を一貫したテーマへ寄せます。販売ページの画像を見ただけで「このゲームだ」と分かる状態が、ツールとの差別化になります。

### 5. 販売物としての信頼を明文化する

BOOTHではダウンロード商品が購入履歴・ライブラリから取得され、ZIP形式では購入者側に解凍環境が必要です。[2] したがって、配布ZIPの中に`AutoBeat5`フォルダ、起動手順、対応OS、対応形式、既知の制約、問い合わせ先、ライセンス、更新履歴を一目で分かる形で入れることが重要です。

販売ページでは、少なくとも以下を明記します。

| 表示項目 | 記載すべき内容 |
|---|---|
| 対応環境 | Windows 10 / 11、必要な空き容量、推奨音声出力、管理者権限の要否 |
| 対応音源 | MP3 / WAV / OGG / FLAC。DRM保護音源・破損音源・極端に長い音源等の既知制約 |
| 遊び方 | D / F / Space / J / K、キー変更、開始までの流れ、オフセット調整 |
| 権利上の注意 | 購入者自身の音源を読み込む用途であり、ゲームに市販曲を同梱しないこと |
| 作品内容 | 自動生成であること、譜面品質が曲により異なること、更新予定の範囲 |
| サポート | 問い合わせ先、ログの取得方法、対応方針、更新履歴 |

BOOTHでは販売商品について画像・タイトル・説明を含め年齢制限や禁止商品への該当性が確認され、必要に応じてR-18設定や非公開化の措置が取られます。[3] ご褒美画像を活用する場合は、**作品本体、サムネイル、紹介画像、説明文を一体として全年齢表現に保つのか、適切に区分するのか**を公開前に決める必要があります。

## 初版販売前の品質ゲート

次の5つを満たすまでは、「完成版」より**限定テスト版／体験版**として扱うことを推奨します。

| ゲート | 合格条件 |
|---|---|
| 初回体験 | 初見テスターが説明なしでデモ曲を完走し、自前曲を1つ解析できる |
| 譜面品質 | 複数ジャンル・BPM帯でBEGINNER〜EXPERTを人間が試遊し、問題を分類済み |
| 音声・環境 | MP3 / WAV / OGG / FLAC、複数の出力機器、複数Windows PCで起動・解析・再生を確認済み |
| 購入者体験 | ZIP解凍から起動、FAQ参照、再起動後の保存、更新後のデータ維持までを別PCで確認済み |
| 権利・表示 | 同梱音源・画像・フォント・効果音・外部ライブラリの利用条件とクレジットを照合済み |

## 3段階の販売ロードマップ

### フェーズA：販売できる最小商品へ（P0）

チュートリアル曲、キャリブレーション、譜面プレビューと再生成、エラー説明の改善、実機テスト表、販売ページの核となるスクリーンショット・短尺動画を完成させます。ここで体験版を配布し、初見者が「解析開始から1曲プレイ」まで到達できるかを観察します。

**成功基準:** 初見者が手助けなしで遊び始め、どの難易度を選んだか、どこで迷ったか、音ズレを感じたかを報告できる。

### フェーズB：買う理由を強める（P1）

リザルト画像、称号・実績、曲別設定、UIテーマ、解放演出を完成させます。プレイヤーが遊んだ記録を残したくなる体験へ進めます。また、購入後の信頼を作るため、バージョン番号、変更履歴、セーブ移行方針、簡潔なサポート窓口を用意します。

**成功基準:** 商品ページの静止画と短い動画だけで、通常の音楽プレイヤーや解析ツールではなく、演奏ゲームとしての魅力が理解できる。

### フェーズC：熱量の高い層へ広げる（P2）

手動譜面調整、コントローラ、コミュニティ共有、モバイル移植を検討します。Android/iOS版は現行Python/Pygame基盤の単純移植ではなく、Windows版で譜面仕様とプレイ感を検証してから、GodotまたはUnity等で別途実装するのが安全です。

**成功基準:** 自動生成で満足したプレイヤーが、好みの曲の譜面をさらに作り込み、長期的に遊び続けられる。

## 次の1スプリントで実装する提案

販売品質を最短で押し上げる次の実装は、以下の順を推奨します。

1. **キャリブレーション画面**: メトロノーム入力からTiming Offset候補を作る。音ゲーとしての信頼を最優先で補強する。
2. **固定デモ曲＋チュートリアル譜面**: 権利処理済み素材を前提に、起動後の最初の3分を設計する。
3. **解析後の譜面概要画面**: BPM、ノーツ数、密度、推奨難易度、生成プリセット、再生成を表示する。
4. **曲別設定の保存**: 曲ごとのオフセット、速度、最後に遊んだ難易度を保存する。
5. **リザルトPNGカード**: プレイヤーが成果を持ち帰れる形にする。

この順序なら、コアの自動生成という価値を守りながら、初見者の不安を減らし、販売ページで見せられる要素も同時に増やせます。

## 権利・販売上の重要な前提

本作が購入者のローカル音源を解析するだけで、その音源をゲーム配布物・動画・スクリーンショットに含めない設計なら、販売時のリスクを大きく抑えられます。一方で、市販曲や配信曲をゲーム内へ同梱する場合は、ゲーム目的の複製について事前に権利者への利用条件確認が必要であり、市販CD等の音源には著作隣接権の許諾も別途必要になります。[1]

また、著作物を公開利用する場合には、営利・非営利を問わず、原則として権利者の許諾または公開済みガイドラインの確認が重要です。[4] 個別の権利処理は作品・音源・配布地域で異なるため、販売確定前に権利者または専門家へ確認してください。本資料は法的助言ではありません。
