# AutoBeat 5 発展バックログ

**対象:** Windows版 AutoBeat 5

**目的:** 現在の「自分の音源から譜面を自動生成して遊べる」基盤を、初見者が迷わず遊べ、継続して楽しみ、将来は同人ゲームとして安全に配布・販売できる作品へ発展させる。

## 現在地

### 2026-10-02追加: Steam体験版の90秒制限（リリース準備時に実装）

持ち込み音源を1回最大90秒に制限し、90秒以下の音源はフルプレイを許容する。
既存のお試しプレイ・練習・結果保存・ビルドの区別に影響があるため、現時点では実装しない。
製品版開発後、体験版ビルドの分離と一緒に着手する。決定事項・未決定事項・受入確認は
[Steam体験版の実装計画](steam_demo_plan.md)を参照。

AutoBeat 5には、音源読込・解析、5難易度の譜面生成、判定・コンボ・スコア、長押し、低難易度の同時押し禁止、3秒カウントダウン、曲末までの再生維持、レーン別ヒットエフェクト、長押し終端キャップ、設定、画像解放、ギャラリー、Windowsビルドが実装されている。直近のWindows回帰テストでは27件が成功している。

> 今後は、機能数を増やすより先に、**初回体験、同期の信頼、譜面品質の説明可能性、第三者へ渡せる配布品質**を整えることが優先である。

## 優先順位の考え方

| 優先度 | 意味 | 着手判断 |
|---|---|---|
| P0 | ベータ配布・販売前に必要 | 作品の理解、安定性、権利、導入の不安を直接減らす |
| P1 | 初版の商品価値を強くする | 継続プレイ、達成感、見た目の固有性を増やす |
| P2 | コアユーザーや市場を広げる | 開発規模が大きいため、初版の反応を見て判断する |

## P0: 次に残っている必須項目

| 項目 | 解決する課題 | 実装の完成条件 | 開発規模 |
|---|---|---|---|
| **キャリブレーション画面** | 音ズレを数値設定だけでは解決しにくい | クリック音に合わせた入力からTiming Offset候補を提示し、適用・再試行・手動調整を選べる | 中 |
| **固定デモ曲とチュートリアル** | 初回に自前音源を用意させると体験開始が遅い | 権利処理済みの短い曲で、キー・長押し・ポーズ・リザルトを自然に学べる | 中 |
| **解析後の譜面概要と再生成** | 自動譜面の当たり外れを事前に判断できない | BPM、ノーツ数、密度、推奨難易度、長押し・同時押し数を表示し、生成プリセットを選んで再生成できる | 中 |
| **実音源の人間プレイ評価** | 自動テストだけでは譜面の音楽性を保証できない | 一旦保留。解放システム導入後、複数ジャンル・BPM帯・4形式をBEGINNERからEXPERTまで人間が試遊し、問題を分類する | 中 |
| **別PC受入テスト** | 開発PCでしか動かないリスクがある | Python未導入のWindows 10/11環境で、ZIP解凍、起動、解析、再起動、保存を確認する | 小 |
| **軽量な配布ビルド** | 現行PyInstaller配布物が不要な依存を含み大きい | クリーンな専用仮想環境から必要最小限でビルドし、不要な機械学習・テスト依存を除外する | 中 |
| **配布ルート資料** | 購入者が起動・音源選択・障害対応で迷う | ZIP直下に起動手順、対応形式、既知制約、FAQ、更新履歴、ライセンスを配置する | 小 |

### P0で最初に作るべき機能

最初の実装候補は**キャリブレーション画面**である。音楽ゲームでは、操作感と判定の信頼が土台になる。自動譜面の出来が良くても、プレイヤーが「自分の入力が遅いのか、音が遅れているのか」を判断できなければ、評価は下がる。

次に、**固定デモ曲とチュートリアル**を作る。これにより、購入者は自前音源の解析品質に左右される前に、ゲームとしての操作感を理解できる。デモ曲はオリジナル曲または利用条件を明確に確認できる素材だけを用いる。

## モバイル対応の位置付け

Android/iOSは可能だが、現行のPython/Pygame/librosa構成をそのまま移す対象ではない。Windows版で譜面JSON、難易度規則、判定窓、演出、販売の仮説を検証してから、GodotまたはUnityなどのモバイル対応基盤でゲーム部分を再実装するのが安全である。

モバイル版では、端末内の軽量音源解析とキャッシュを基本にする。重い解析をサーバーへ移す方針は、通信、音源の取扱い、継続費用、プライバシーの論点が増えるため、初期版では避ける。

## 実装しない方がよい順序

次の項目は魅力的だが、P0より先に着手しない。

| 後回しにする項目 | 理由 |
|---|---|
| オンラインランキング・SNS連携 | サーバー運用、不正対策、アカウント・個人情報の負担が急に増える |
| 市販曲の同梱 | 権利処理の難易度が高く、初版の価値検証を遅らせる |
| iOS版の先行開発 | 現行基盤を再利用できず、Windows版の改善知見を得る前に工数が増える |
| 大規模なストーリーモード | 自動譜面で遊ぶ核を検証する前に制作量だけが増える |

| スプリント | 実装・検証内容 | 完了条件 |
|---|---|---|

## 次の一手

次に実装するのは、**キャリブレーション画面**を推奨する。これを完了すると、音ズレ相談への対応が「設定で調整してください」から「ゲーム内の手順で自己解決できます」へ変わる。音源解析の品質、難易度調整、配布テストの結果を正しく受け取るための基盤にもなる。

その次に、固定デモ曲とチュートリアル、解析後の譜面概要を連続して実装する。ここまで完成すれば、知人向けベータ配布で得るフィードバックの質が大きく上がり、販売前に何を直すべきかをデータとして判断できる。
