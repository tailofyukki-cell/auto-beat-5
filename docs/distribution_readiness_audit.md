# AutoBeat 5 同人販売・第三者配布準備監査

**監査日:** 2026-08-19  
**対象:** `dist/AutoBeat5/` のWindows配布物、およびビルド設定・付属資料  
**結論:** 現行ビルドは**開発者・少人数テスター向けの動作確認版**としては成立しています。しかし、配布容量と購入者向けパッケージの両方に重大な未整備があるため、現状のまま一般配布・有償販売へ進むことは推奨しません。

## 1. 現在の配布物の実測状況

| 項目 | 確認結果 | 評価 |
|---|---:|---|
| 配布形式 | PyInstaller `onedir`形式 | 妥当。EXE単体ではなくフォルダ全体を渡す必要がある。 |
| 実行ファイル | `AutoBeat5.exe`、約80.7 MB | 起動可能なWindows実行ファイルとして生成済み。 |
| フォルダ全体 | 約1,400.4 MB | **一般配布には過大。最優先で削減が必要。** |
| 日本語フォント | `_internal/fonts/NotoSansCJK-Regular.ttc`を同梱 | Windows環境差による豆腐文字を防ぐ方針として正しい。 |
| 第三者ライセンス通知 | `_internal/licenses/THIRD_PARTY_NOTICES.md`を同梱 | 技術的には同梱済み。ただし購入者が見つけやすい場所にも案内が必要。 |
| ご褒美設定 | `rewards/reward_config.json`を同梱 | 外部画像を追加できる構成として機能する。 |
| 配布物ルートの案内 | `README`、変更履歴、利用条件がない | **第三者配布前の必須不足。** |
| 再現可能ビルド | `build_windows.bat`あり | ビルドできるが、現在のPython環境へ依存しすぎる。 |

現在の1.4 GBというサイズは、ゲームの実装規模そのものではなく、PyInstaller設定が`librosa`、`scipy`、`sklearn`、`numba`などに`collect_all()`を適用し、さらにビルド環境の`torch`、`onnxruntime`、`cv2`、`transformers`等まで取り込んでいることによるものです。実測では`onnxruntime`だけで約383.5 MB、`torch`が約312.6 MB、`cv2`が約98.3 MBを占めています。これらはAutoBeat 5の`requirements.txt`に記載されていません。

> 現状の最大課題はゲーム性ではなく、**開発環境の依存関係が配布物へ流入していること**です。まず容量と構成を正常化してから、販売用パッケージを作る必要があります。

## 2. 販売・第三者配布の準備判定

| 区分 | 判定 | 条件 |
|---|---|---|
| 自分のPCでの利用 | **可能** | 直近のWindows回帰テストと起動確認済み。 |
| 少人数の技術テスト | **可能** | `dist/AutoBeat5/`全体を渡し、ベータ版として不具合報告を集める。 |
| 無料の一般ベータ配布 | **未推奨** | 1.4 GBの容量、導入案内不足、別PC受入未完了を先に解消する。 |
| 有償販売 | **不可（準備中）** | 販売パッケージ、受入テスト、初回体験、サポート・権利表示を完成させる。 |

## 3. まずレベルアップすべき販売品質

### P0: 初回の15分を「ゲーム体験」にする

AutoBeat 5の価値は「自分の曲を譜面にできる」ことです。しかし、購入直後に音源を用意させ、解析待ちや難易度選択へ進ませるだけでは、ツールとして見られやすくなります。最初に権利処理済みの短いデモ曲と固定チュートリアル譜面を用意し、操作、長押し、ポーズ、速度、リザルトまでを一曲で体験させます。

その後に「自分の曲を解析する」導線へ進めれば、購入者はゲーム側の基準を理解してから自前音源を選べます。市販CDや配信音源をゲーム本体へ同梱する場合は、著作権に加え、音源製作者・アーティスト等の著作隣接権の許諾も必要です。[1]

### P0: 音ズレと譜面の当たり外れを自己解決可能にする

音楽ゲームでは、プレイヤーが「判定が合わない」と感じた時に、その原因が音ズレか譜面か操作かを切り分けられることが信頼につながります。クリック音に合わせてキーを押すキャリブレーション、曲別Timing Offset、リザルトの早い／遅い分布を優先実装します。

自動譜面については、解析後にBPM、ノーツ数、密度、推奨難易度を表示し、「控えめ」「標準」「にぎやか」などの生成プリセットと再生成を用意するべきです。自動生成の限界を隠すのではなく、プレイヤーが調整できる体験に変えることが重要です。

### P0: 別PCでの受入テストを販売条件にする

開発PCで起動することと、購入者PCで遊べることは別です。Python未導入のWindows 10/11環境、異なる音声出力（内蔵・有線・Bluetooth）、実際のMP3/WAV/OGG/FLACで、以下を確認します。

| テスト項目 | 合格条件 |
|---|---|
| 導入 | ZIP解凍後にフォルダ全体からEXEを起動できる。管理者権限を要求しない。 |
| 初回 | デモ曲または自前音源で、開始からリザルトまで進める。 |
| 音源 | MP3/WAV/OGG/FLACで解析・難易度選択・プレイ・曲末再生が完了する。 |
| 保存 | 設定、速度、スコア、解放状態、譜面キャッシュが再起動後も維持される。 |
| 失敗時 | 非対応・破損音源でクラッシュせず、原因と対処を表示する。 |
| 更新 | 新版のフォルダへ更新しても、セーブデータが読み込める。 |

### P1: 「見せたくなる」成果を作る

販売ページと口コミのためには、解析機能の説明だけでなく、演奏結果を見せる素材が必要です。曲名、難易度、ランク、精度、最大コンボを含む結果カードをPNG保存できるようにし、プレイヤーが任意にSNSなどへ投稿できる構成を推奨します。アカウント連携や自動投稿は不要です。

同時に、タイトル、レーン、判定、解放演出、効果音を一貫したテーマへ整えます。静止画一枚で「これはAutoBeat 5だ」と分かる視覚的な固有性が、同人ゲームとしての価格納得感につながります。

### P1: 販売ページと運用を商品に含める

販売ページには、対応OS、必要空き容量、対応形式、キー操作、既知の制限、音源の権利上の注意、問い合わせ先、更新履歴を明記します。BOOTHのダウンロード商品では、購入者は購入履歴またはライブラリからファイルを取得し、ZIP形式では購入者自身が解凍する必要があります。[2] 導入手順を短く分かりやすくすることは、実装品質の一部です。

ご褒美画像や販売ページの紹介画像を用いる場合、作品本体・サムネイル・説明文を含めて全年齢表現にするか、適切な年齢区分にするかを事前に決めます。BOOTHでは商品説明・画像・タイトルも含めて規約適合性が確認されます。[3]

## 4. ビルド・パッケージングの改善ロードマップ

### ステップA: 専用のクリーンビルド環境を作る

`build_windows.bat`は現在、実行中の`python`に対して依存関係を直接インストールします。この方式では、Miniconda等の普段使い環境に存在する不要なパッケージがPyInstaller解析へ混ざりやすく、今回の巨大化につながります。

販売用ビルドは、専用の仮想環境を作り、`requirements.txt`にある`pygame`、`librosa`、`soundfile`、`numpy`、`PyInstaller`だけを導入して実行します。`AutoBeat5.spec`も、広範な`collect_all()`をやめ、実際に必要なデータ・バイナリ・隠しimportだけを明示的に収集します。これにより、`torch`、`onnxruntime`、`cv2`、`transformers`、各ライブラリのテスト一式を配布物から除外できます。

### ステップB: 購入者向けのフォルダ構成にする

販売用のZIPは、次のように購入者が迷わない構造にします。

```text
AutoBeat5_v0.1.0-beta_Win64/
├─ AutoBeat5.exe
├─ README.txt                 # 最初に読む導入・操作・FAQ
├─ CHANGELOG.md               # バージョンと変更履歴
├─ LICENSES/
│  ├─ THIRD_PARTY_NOTICES.md
│  └─ NotoSansCJK-OFL-1.1.txt
├─ rewards/
│  ├─ reward_config.json
│  └─ README.txt
└─ _internal/                 # 実行に必須。利用者は通常触れない。
```

`README.txt`はルートに置き、少なくとも「EXE単体ではなくフォルダ全体を解凍して起動する」「Windows 10/11向け」「音源の読み込み方法」「対応形式」「音ズレ調整」「不具合報告時に添える情報」を書きます。第三者ライセンス通知も見つけやすい`LICENSES/`へ複製または案内を置きます。

### ステップC: リリースZIPと完全性情報を作る

ビルド後、実行中のAutoBeat5を停止し、フォルダ全体を`AutoBeat5_vX.Y.Z_Win64.zip`へ圧縮します。続けてSHA-256ハッシュを`SHA256SUMS.txt`として添付します。これは改ざん防止そのものではありませんが、ダウンロード破損や配布ファイルの取り違えを切り分ける助けになります。

公開前に、ZIPを別フォルダまたは別PCへ展開し、**そのZIP由来のEXEだけ**を起動して受入テストを実施します。開発フォルダのEXEを起動して確認しても、パッケージ品質の確認にはなりません。

### ステップD: 販売用の信頼表示を用意する

コード署名は初版の絶対条件ではありませんが、Windowsの警告を減らし、配布元の信頼性を高めるため、販売継続を決めた段階で検討します。少なくとも、公式配布場所、リリース日、版番号、ファイルハッシュ、更新履歴を一箇所に集めます。

## 5. 販売開始前の最小チェックリスト

| 分野 | 販売開始の最低条件 |
|---|---|
| 容量 | 専用環境で再ビルドし、不要なAI・画像処理ライブラリを除外して配布容量を大幅に削減する。 |
| 導入 | ルートREADME、ライセンス、変更履歴、FAQを同梱する。 |
| 受入 | 少なくとも別環境で、解凍・起動・音源解析・プレイ・曲末・保存を確認する。 |
| 体験 | デモ曲またはチュートリアルを収録し、音源がない購入者にも価値を伝える。 |
| 品質 | キャリブレーション、解析失敗時の案内、曲別調整を整える。 |
| 権利 | 同梱する音源・画像・フォント・効果音・ライブラリの利用条件を一覧化する。 |
| 販売ページ | 対応環境、対応形式、制約、操作、問い合わせ、更新方針を明記する。 |

## 6. 今の推奨アクション

1. **次の開発作業として「クリーンビルド・軽量パッケージ化」を実施する。** これは配布準備の最大ボトルネックであり、まず解決すべきである。
2. 軽量化後のZIPを作り、知人2〜3名へ限定配布して、別PC・別音源・別音声出力のテストを依頼する。
3. そのフィードバックを反映後、デモ曲・キャリブレーション・販売ページ素材を整え、無料ベータ公開へ進む。
4. 有償販売は、体験版または限定ベータの導入率・不具合率・譜面品質評価を確認した後に判断する。
