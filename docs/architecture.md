# AutoBeat 5 アーキテクチャ設計

**作成者:** Manus AI  
**対象:** Windows 10 / 11  
**最終更新:** 2026-08-18

## 1. 技術選定

本作は、**Python 3.11 + Pygame + librosa** を採用する。Pygameは2D描画、入力、音源再生を一元化できるため、5レーンの縦スクロールとフレーム非依存の判定処理を小さな実行基盤で実装できる。librosaはBPM、beat、onset、STFT、周波数帯域エネルギー、持続候補の解析に用いる。音楽分析をゲームループと独立したワーカースレッドに置くことで、初回解析中の画面停止を避ける。

| 層 | 採用技術 | 責務 |
|---|---|---|
| プレゼンテーション | Pygame | 画面遷移、2D描画、入力、アニメーション、ギャラリー |
| ゲームコア | Python標準ライブラリ | ノーツ状態、時間判定、コンボ、スコア、リザルト |
| 音源再生 | `pygame.mixer.music` | MP3 / WAV / OGG / FLAC の再生を試行し、再生時刻とゲーム時計を連携 |
| 音楽分析 | librosa + NumPy | BPM、beat、onset、スペクトル帯域、持続候補、楽曲長 |
| 譜面生成 | 自製モジュール | 解析特徴量から難易度別の決定論的な譜面を生成 |
| 永続化 | JSON + SHA-256 | 設定、スコア、履歴、解析キャッシュ、譜面キャッシュ、解放状態 |
| 配布 | PyInstaller | 依存関係を同梱するWindows実行ファイルを生成 |

GodotはMITライセンスで同人販売を含む用途に使いやすい一方、今回は既存のPython音楽解析資産を直接活用すること、少人数開発で解析から生成までを速く検証することを優先する。UnityもWindowsデスクトップ公開に対応するが、収益・資金調達の条件によりプラン変更が必要となる。したがって、初版ではPythonベースでコア体験を確立し、必要時のみゲームエンジン移植を検討する。[1] [2]

> **ライセンス上の注意:** librosaはISCライセンスであり、著作権表示と許諾文を配布物へ含める必要がある。[3] PygameについてもLGPLの本文を同梱し、依存ライブラリのライセンス一覧を配布物に含める。[4] 本書は法的助言ではないため、販売前に配布物と依存バイナリのライセンスを再確認する。

## 2. モジュール境界

```text
src/
├── app.py                 # アプリケーション起点と画面状態遷移
├── models.py              # Note / Chart / AnalysisResult / Difficulty
├── persistence.py         # 設定・キャッシュ・成績のJSON永続化
├── audio_clock.py         # 再生時計・一時停止・Timing Offset
├── analyzer.py            # 音源解析とフォールバック
├── chart_generator.py     # 解析結果から決定論的に譜面生成
├── chart_validator.py     # 人間に不可能な配置の検査・補正
├── gameplay.py            # 判定・長押し・スコア・コンボ
├── rewards.py             # ご褒美画像検出・解放・ギャラリー
└── ui.py                  # Pygame描画部品と画面
```

各ノーツは、種類に依存しない共通構造を持つ。通常ノーツは`end_time = null`、長押しノーツは`end_time > time`で表現し、同時押しは同一時刻の複数ノーツとして記録する。この構造により、将来のスライド・スクラッチなどを`kind`で拡張できる。

## 3. 時刻同期と判定

ゲーム時計はフレーム数ではなく単調増加時計に基づく。音源再生開始時を基準に、`楽曲再生秒 + Timing Offset`を判定対象の時刻とする。描画は毎フレーム更新するが、ノーツのY座標、キー入力の判定、MISS判定のいずれも時刻差で評価する。標準判定幅は以下とし、設定ファイルから調整できる。

| 判定 | 絶対誤差 | 得点係数 | コンボ |
|---|---:|---:|---|
| PERFECT | 45 ms以下 | 1.00 | 継続 |
| GREAT | 90 ms以下 | 0.80 | 継続 |
| GOOD | 140 ms以下 | 0.50 | 継続 |
| MISS | 140 ms超過、または未入力 | 0.00 | リセット |

長押しでは開始・保持・終端を内部評価する。開始時は通常ノーツと同じ判定幅、保持中は早期離鍵をMISS相当、終端は離鍵時刻との差を評価する。初版では、入力物理制約を譜面生成側で先に回避し、プレイ側は一貫した判定を行う。

## 4. 自動譜面生成パイプライン

```text
音源ファイル
  └─ SHA-256でキャッシュキーを作成
       └─ PCMへデコードして特徴抽出
            ├─ BPM / beat / 小節候補
            ├─ onset時刻・強度
            ├─ 低・中低・中高・高域のエネルギー
            ├─ 打楽器らしい広帯域トランジェント
            └─ 持続候補
                 └─ 難易度別イベント選別
                      └─ レーン割当・同時押し・長押し・連打へ変換
                           └─ プレイ可能性検証・補正
                                └─ charts/<hash>/<difficulty>.json
```

生成処理は、曲ファイルのSHA-256と難易度名から導くシードを保存する。ただしレーン選択は可能な限り決定規則で行い、同じ音源と同じ版の生成器では同じ譜面を再現する。低域ピークはD/F、高域ピークはJ/K、強い広帯域トランジェントと強拍はSpaceを優先する。短いonsetは通常ノーツ、連続onsetは連打候補、持続候補は長押し候補、同一時刻の複数帯域ピークは同時押し候補とする。

## 5. 画面と非同期処理

タイトル、楽曲選択、解析進捗、難易度選択、ゲーム、リザルト、ギャラリー、設定、キーコンフィグを単一の状態機械で遷移させる。音楽分析は専用スレッドで実行し、`progress`と`stage`をスレッド安全なキューでUIへ通知する。破損ファイルや分析失敗時は、ファイル名とエラー理由を表示する。BPMが得られない場合は120 BPMの規則的な候補と強度ピークだけを使うフォールバック譜面を生成する。

## 6. データ配置

Windowsではユーザーデータを`%APPDATA%/AutoBeat5/`、開発時にはプロジェクト直下の`userdata/`へ保存する。音源そのものはコピーせず、絶対パス・ファイルハッシュ・メタデータだけを記録する。譜面と解析結果はファイルハッシュ単位で分離し、元ファイル変更時は再解析する。

| データ | 保存先 | 主な内容 |
|---|---|---|
| 設定 | `settings.json` | キー、音量、ノーツ速度、Timing Offset、画面 |
| プレイ記録 | `profile.json` | 累積スコア、解放済み画像、ハイスコア、履歴 |
| 解析キャッシュ | `cache/<hash>.json` | BPM、beat、onset、帯域特徴、曲長 |
| 譜面 | `charts/<hash>/<difficulty>.json` | ノーツ、生成器版、シード、難易度 |
| ご褒美設定 | `rewards/reward_config.json` | 画像名と必要累積スコア |

## 7. 段階的完成基準

初回実装では、正常な音源の読み込み、分析、通常ノーツ、5レーン、判定、スコア、コンボ、リザルト、設定保存、解析・譜面キャッシュを動作させる。次の実装単位で同時押し、長押し、連打、難易度固有ルール、画像解放・ギャラリーを追加し、それぞれにユニットテストと手動プレイテストを設ける。配布段階ではWindowsでのビルドを自動化し、実行ファイル、`rewards/`、ライセンス文書、操作説明を同梱する。
